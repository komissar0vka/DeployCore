# База данных

PostgreSQL 16 хранит данные в именованном томе Compose. API проверяет подключение через SQLAlchemy 2 и запрос `SELECT 1`. При старте сервера Alembic применяет миграции под транзакционной advisory-блокировкой PostgreSQL. Версия схемы хранится в `alembic_version`.

Миграция `0001_system` создаёт четыре таблицы. `installation_settings` содержит единственную строку с ключом 1. Она блокируется при завершении настройки и при изменении ролей. `users` хранит нормализованный уникальный логин и хеш пароля. В `sessions` хранятся SHA-256 идентификатора сессии, время активности и абсолютное истечение. `audit_events` хранит события, сведения о субъекте и объекте и безопасные метаданные. Индексы журнала поддерживают сортировку по времени и подсчёт недавних неудачных входов.

| Этап | Планируемые сущности |
| --- | --- |
| 4 | `software`, `software_versions`, `installer_blobs` |
| 5 | `jobs`, `job_targets`, `job_attempts`, `job_log_entries` |
| 6 | `groups`, `group_members` |

Использовать UUID для публичных идентификаторов, отметки времени UTC, внешние ключи и ограничения уникальности. Создание первого администратора и завершение настройки выполняются в одной транзакции с блокировкой записи состояния установки. Аренда задания должна назначаться атомарно. Историю попыток, журнал и результаты хранить по целевому устройству. Индексы подбирать по фактическим запросам, включая выборку готовых заданий, поиск по устройствам и журналу. Миграции проверять на пустой БД и при обновлении с предыдущей версии.

Миграция `0002_devices` добавляет `devices`, `agents`, `enrollment_tokens`, `device_inventory`, `installed_software` и `device_events`. UUID установки сопоставляется с устройством. Регистрация сериализуется блокировкой токена и устройства или транзакционной advisory-блокировкой для нового UUID. При повторе запрос с тем же токеном, UUID и ключом возвращает существующее устройство в пределах срока токена. Токен восстановления содержит ссылку на устройство и рассчитан на одну регистрацию. Новый токен восстановления отзывает предыдущий.

Инвентаризация заменяется в транзакции. Сервер сравнивает хеш нормализованного снимка, чтобы не добавлять повторное событие при идентичных данных. При удалении устройства хранятся идентификатор, запись об отзыве и история событий. IP и инвентарь удаляются.
