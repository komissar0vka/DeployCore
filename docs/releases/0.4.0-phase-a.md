# DeployCore 0.4.0 · подэтап A

## Что изменилось

- Постоянное боковое меню на широком экране и диалог навигации на мобильном. Разделы, состояние фильтров поиска и открытая карточка устройства поддерживают адреса с фрагментом URL и переходы «Назад» и «Вперёд».
- В верхней панели работают поиск устройств по имени, FQDN или IP, уведомления из сводки, профиль, выбор темы и выход. Ctrl+K или Command+K переводит фокус в поиск. Светлая тема используется по умолчанию, выбор хранится в браузере. Язык по-прежнему берётся из настроек экземпляра и по умолчанию русский.
- На дашборде есть карточки-метрики, переходы к отфильтрованному списку, доступность, версии агентов и события. «Развёртывание» открывает существующую установку и токены Windows Agent. «Инвентаризация» открывает существующие снимки агента.
- Список устройств имеет режимы таблицы и карточек, фильтр состояния, сортируемые колонки и выделение текущей страницы. Выделение сохраняется при перелистывании в рамках того же фильтра. Выбранные имена можно скопировать. Карточка устройства содержит обзор, оборудование, программы и события. Отзыв ключа и удаление требуют подтверждения.
- «Карта помещений», «Программы», «Задания», «Отчёты» и «Лицензия» доступны в навигации с указанием текущего состояния. Карта, каталог, очередь, генерация отчётов и лицензирование пока не реализованы.

## Файлы

- Созданы `apps/web/src/console-shell.tsx`, `apps/web/src/components/ui/button.tsx`, `apps/web/src/components/ui/dialog.tsx` и `apps/web/src/components/ui/dropdown.tsx`.
- Обновлены точки входа, дашборд, список и карточка устройств, общие UI-компоненты, темы и существующие административные экраны в `apps/web/src/`.
- В `apps/server/deploycore/device_api.py` добавлены необязательные параметры сортировки `sort` и `direction` для `GET /api/v1/devices`. Прежние параметры, порядок по умолчанию и формат ответа сохранены. Обновлены OpenAPI, описание REST API и изолированный smoke-тест.
- Миграций PostgreSQL на подэтапе A нет. Авторизация, роли и регистрация агентов продолжают использовать существующие API.

## Запуск и проверки

Из корня DeployCore выполните стандартный запуск по README. Для проверки без затрагивания рабочей базы выполните `deploy/scripts/smoke.sh`. Он поднимает отдельный проект на локальном порту 18443 с временной БД и TLS; порт можно изменить через `SMOKE_PORT`.

Для локальной сборки интерфейса выполните `npm ci` и `npm run build` в `apps/web`. Для тестов сервера установите `apps/server/requirements-test.txt` в виртуальное окружение и выполните `python -m pytest -q` из `apps/server`.

## Результаты проверки

- Backend. Прошли 14 тестов pytest. Сквозной тест PostgreSQL подтвердил сортировку до пагинации, прежний поиск, проверку допустимых параметров, роли, регистрацию агента, heartbeat и сохранение инвентаризации после перезапуска.
- Frontend. TypeScript и Vite собрали приложение. Chromium проверил интерфейс на 1440 и 360 px с тестовыми ответами API. Пройдены сценарии поиска, сортировки, группового выделения и копирования, уведомлений, карточек, подтверждений и ограничений Viewer. Проверено сохранение темы после перезагрузки.
- Изолированный Docker Compose. Проверены HTTPS, OpenAPI, контрольные суммы EXE/MSI, отсутствие новых миграций и восстановление readiness после перезапуска БД.
- Рабочий экземпляр 0.3.x, его база и соседние сервисы сохранили прежнее состояние. Этот подэтап не включает приёмку MSI или установки программ на Windows.
