# Модель безопасности

Хост публикует только HTTPS-порт Nginx. PostgreSQL и FastAPI используют внутреннюю сеть Compose. Nginx получает сертификат и ключ через монтирование с доступом только на чтение. Внешним клиентам нужен доверенный сертификат для имени сервера. Ответ readiness содержит только состояние доступности.

## Первоначальная настройка и учётные записи

- Первичный мастер требует случайный секрет из `DEPLOYCORE_SETUP_TOKEN`. Создание пользователя, запись настроек и аудит проходят в одной транзакции под блокировкой строки установки. Повторное завершение возвращает 409.
- Пароли хешируются Argon2id. Сервер хранит хеш случайного идентификатора сессии. Cookie использует префикс `__Host-`, `HttpOnly`, `Secure`, `SameSite=Strict` и путь `/`. Сессия истекает через 30 минут без авторизованных запросов или через 12 часов с момента входа. Запросы мониторинга не продлевают сессию. Выход удаляет её из БД.
- Login и Setup требуют HTTPS origin и пользовательский заголовок. Авторизованные изменения дополнительно проверяют CSRF-токен, привязанный к сессии. Панель хранит его в памяти.
- В течение 10 минут допускаются пять неудачных проверок пароля на логин либо 30 на исходный IP. После порога возвращается 429 с `Retry-After`. Для одинакового логина и IP проверки сериализуются в PostgreSQL. Nginx перезаписывает адрес клиента. В журнал попадают попытки, для которых проверялся пароль.
- Super Admin управляет пользователями, ролями, настройками и читает аудит. Administrator и Viewer могут читать доступные настройки. Право Administrator на операции с устройствами, ПО и заданиями предусмотрено для следующих этапов.
- Аудит хранит тип события, время, субъект, объект и ограниченные метаданные. Тексты паролей, установочный секрет, идентификатор сессии и CSRF-токен в журнал не передаются.

## Границы доверия следующих этапов

- Токены регистрации имеют срок действия и квоту. У агента собственный отзываемый секрет. Сервер хранит хеши токенов, агент защищает свой секрет средствами Windows и ACL.
- Установка разрешена по опубликованной версии из каталога. Агент сверяет SHA-256 перед запуском, использует типизированные операции и запускает MSI или EXE напрямую с валидируемыми аргументами. Манифест не принимает shell-команды или произвольные пути. Политики Windows и средства защиты продолжают действовать.
- Аудит фиксирует субъекта, действие, ресурс, время и исход. Секреты, пароли и заголовки авторизации исключаются из журналов и Git.

## Windows Agent

Enrollment-токен имеет срок, квоту и отзыв. Сервер хранит SHA-256 токена и индивидуального случайного ключа агента. Агент сохраняет новый UUID и ключ до первого запроса, чтобы безопасно повторить регистрацию после потери ответа. Имя компьютера используется как метаданные и не даёт права на существующую регистрацию. Восстановление требует одноразового токена для конкретного UUID и заменяет предыдущий ключ.

Агент проверяет HTTPS, включая цепочку и имя сервера, и отклоняет HTTP-переадресации. Состояние сохраняется через DPAPI с ACL для администраторов и LocalSystem. Для аппаратного снимка запускается фиксированный локальный CIM-запрос с ограниченным временем. Программы читаются по полям имени, версии и издателя из записей реестра.
